# 单项决策与宿主问答

主线程在确实需要用户作一个决定或接续一个待答事项时读取本文件。[主线程协调](coordination.md) 负责判断何时问、保留状态和应用裁决。本文件随 Insight 分发。

## 形成一个决策问题

1. 先查在当前范围内可核实的事实。选会改变主张、证据路线、读者目标或裁决的上游决定。用户已经确定的事项直接沿用。
2. 简述为什么现在要决定，以及各答案会改变哪些工作。先把彼此支持的主张、机制和验证方法组织成一条论证。只有指向不同主线或不同资源投向的方案才作为独立候选。
3. 候选围绕同一个取舍。把有依据的推荐放在第一位，每项写清实际收益和代价（若前文已充分展开候选论证，选项中每项只保留 1 句核心收益与代价，不重复大段正文）。通常用二至三个有效选项。开放题可以直接接受自由回答。保留用户自填、组合或跳过的空间，有宿主自带的自由输入时直接使用。
4. 发出前记下问题、材料版本和受此决定影响的工作。若已有待答事项，先解释或接续原题。角色代理仅向主线程建议问题。平台权限确认沿用宿主自己的流程。

## 发问与待答

检查当前工具定义和模式。合适的原生入口可用时，由主线程实际发一题。参数错误先修正，发送结果不明确时先确认接收状态再重试；若原生入口不可用、缺少接收端或修正后仍调用失败，立即降级为下方“文本问答”，在交代暂停事项后交还本轮，绝不在未获用户确认时自行假定选择并推进。

- **同步问答**等待调用返回，再处理实际答复。
- **异步问答**在已接收或 pending 时保留待答状态及真实标识。只先做对各合理答案都有用的工作，然后按宿主提供的方式等待。沉默、工具仅返回已接收、预选、超时或回合结束都不解除依赖。迟到答复按标识匹配，无标识时核对问题和材料版本。已经关闭或失效的旧问题保持关闭。
- **文本问答**用于缺少或无法使用合适的原生入口时。呈现同一题（以明确问句或清楚的选项提示收尾）、推荐项及各自取舍，交代暂停事项，交还本轮并在下一条消息接续。

每个决定只保留一份待答记录。反问时先解释并沿用原题，确认原问题交互已失效后才重呈现。依赖答案的方案、执行和成稿保持暂停。

## 把实际答复应用到写作

| 收到的内容 | 主线程如何接续 |
| --- | --- |
| 明确选择、自由回答或明确采用推荐 | 记录所作决定及其范围，解锁该答案实际解决的工作 |
| 组合答案 | 按用户表达整理主线、辅助项和优先顺序，只有实质冲突才继续澄清 |
| 反问、补充事实或模糊的「继续」 | 回应问题或更新材料，保留原决定的待答状态，除非这条消息明确作出了决定 |
| 跳过、关闭或取消提问 | 停止主动等待该题，记录为未决定。依赖项仍暂停，可继续独立事项 |
| 取消任务或修改范围 | 按明确指示处理受影响的部分，失效的原问题不再接收新决定 |

按 [主线程协调](coordination.md) 更新决定的范围和版本。完整审查的成稿授权按 [红蓝与一次成稿协议](protocol.md) 处理。

## 宿主适配

| 当前宿主 | 映射到的工具与模式 |
| --- | --- |
| Codex | `request_user_input_async` 可用时走异步，`accepted: true` 表示已接收。同步工具按当前模式限制和选项结构调用。 |
| Claude | Claude Code 主线程的 `AskUserQuestion` 可用时走同步。Desktop 的 Chat、Cowork 和 Code 按当前会话暴露的入口判断。 |
| DeepSeek Harness | 当前预设提供 `ask_user_question` 时依其实际定义调用。阻塞模式走同步，定时模式按 `pending` 和 `callId` 接续。明确缺少接收端时用文本问答。 |
| 其他宿主 / 纯聊天 | 按当前会话实际工具定义判断同步或异步问答；无适用原生入口时使用文本问答并在下一条消息接续。 |

工具实际支持自由输入时使用它，否则保留聊天里的自定义回答路径。
