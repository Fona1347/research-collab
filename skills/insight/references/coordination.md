# 主线程协调与交互接口

用于共同立论、处理实质分歧、选择裁决安排和接续既有决定。纯润色没有实质分歧时不加载本文件，不自动创建记录文件。

## 职责边界

| 主体 | 负责 | 返回/使用的结果 |
| --- | --- | --- |
| 主线程与写作 skill | 任务分流、主张发展、证据路线、论证结构、何时需要用户决定、上下文传递 | 有效写作要求、当前问题、论证与成稿包 |
| grill-me | 原生卡片、候选表达、异步等待、回答分类和接续 | 实际答复及其解决的事项；不新增写作流程 |
| 蓝方/红方/成稿方 | 按本轮角色处理获分配的材料 | 论证、审查、文章；需要用户信息时只交问题建议 |

主线程是唯一用户对话入口。`grill-me` 是按需读取的交互规范，不是新增子代理，不持有第二份独立决策状态。写作流程调用其交互规范后仍由同一主线程执行。`grill-me` 不反向启动写作 skill。

## 最小任务状态

在当前聊天维护必要信息即可；没有用户保存要求时不生成表单、日志或数据库：

- **任务要求**：写作目标、受众/用途、允许改动范围、交付阶段、专业直觉及当前主张成熟度。
- **有效决定**：已经决定的事项、实际用户答复、适用材料与影响范围。区分“选方向”“审查取舍”“批准成稿”，不以其中之一冒充另一项。
- **当前材料**：证据、推断、假设的身份，论证连接，材料版本及重要变化。
- **唯一待答问题**：决定事项、为何需要用户、候选与推荐、已有条件、可独立进行和必须等待的工作。真实工具返回标识时保存标识，不编造。

跨回合或上下文压缩时保留这些有效状态。已放弃方向和已排除审计可留作历史，但不混入有效写作要求。

## 何时问、何时继续

只有用户的答案会实质改变主张、证据路线、表达意图或交付范围时，才请求决定。已能由材料和授权范围确定的选择直接处理。能检索确认的事实先查，不把工具可解决的问题交给用户。

| 场景 | 动作 |
| --- | --- |
| 润色、压缩、翻译、明确改写 | 直接完成；只有歧义会改变原意时才问 |
| 已有主张扩写 | 主动补机制、连接理由和意义；另立核心观点或改变证据强度时问 |
| 模糊直觉/从零立论 | 先补足能形成判断的背景，提出可回应的论证。主张、支撑机制和验证合并呈现。多个独立方向确实需要取舍时再问 |
| 已选方向，尚未看到审查 | 继续展开/核查，不再确认方向；完整审查结束后才裁决新出现的事项与成稿 |
| 同一主张和材料已有有效成稿裁决 | 直接编制成稿包，不再确认 |
| 新证据实质改变已作判断 | 只重新提出受影响事项及其原因，其他决定继续有效 |

不要因为文件改名、材料补了出处或版本号递增就让全部裁决失效。判断依据是证据内容与主张是否发生实质变化。

探索中的提问服务于发展观点，例如“若这个机制成立，最先应观察到什么”“现有解释在哪个连接上不足”“这会怎样改变研究优先级”。先提出可回应的候选，允许讨论改变候选；不把所有探索问题都做成强制问卷。

## 向 grill-me 交接当前交互

只有确需提问时，按宿主提供的技能位置读取当前 `grill-me/SKILL.md`。不要硬编码另一工作区路径，不把它设为所有写作任务的前置条件。提供：

1. 本次唯一要决定的事项，以及答案会改变什么。
2. 用户已经确定的目标、主线、约束和已有裁决。
3. 能支持选择的必要背景；候选主张/方案、推荐和理由。
4. 当前是否已有待答问题、真实工具标识（如有），以及收到的新消息。
5. 可独立进行的工作、必须等答复的工作及下一步交付。

发卡前先说明选择甲或乙分别会改变什么。两者若是主张与论据、手段与目标、指标与解释，就把关系写入同一推荐。只有实验资源确实只够做一项时，才把“先测哪个”交给用户。与 grill-me 组合时交接这一个实际取舍。

若该 skill 在宿主确实不可用，说明缺失并直接使用实际可用的原生问答工具：一次一题，推荐第一，合理候选与自由输入；明确选择才解除依赖，反问保留原题待答，独立工作完成后按宿主能力等待。原生工具也不可用才退回文本，不假称调用了 skill 或 UI。

## 回答如何变成有效决定

由同一个主线程按 grill-me 的回答分类更新状态：

- 明确选择或自由决定：记录其实际作用范围，接续已解除依赖的工作。
- 组合答案：整理主线、辅助部分与优先顺序；关系明确且可执行就继续，不为确认理解而再问一遍。只有组合存在会改变结果的冲突才追问。
- 反问：先解释，原题及其标识继续待答；不弹第二张卡，不把反问解释为选择。
- 新材料/补充事实：更新材料，不自动替代尚未作出的选择。沉默、预选项、超时、工具成功或回合结束均不算答复。
- 取消/跳过/范围变化：按 grill-me 规则处理，只终止或更新受影响的分支，避免旧卡片迟到回复覆盖新决定。

独立查阅和有用解释可以继续。依赖未决选择的正式主张、方案、最终稿及操作必须等实际答复。独立工作结束后按 grill-me 与宿主规则等待，不因发卡返回就立刻收尾。

## 裁决的安排

方向分歧大、不同选择会产生大量不同调研时，先选方向，再对审查结果裁决；候选接近、比较成本低时，把主线建议、重要异议处理与成稿授权组成一份可审阅方案，合并裁决。主线程自行选择安排并简短交代，不再问用户选择工作流。

合并裁决时，一张卡片的决定是“是否采用这一份完整且已说明的方案”；不能用三个互不相关的维度拼成三个选项。若某一异议存在独立冲突，先解决该冲突，再请求尚缺的成稿授权。前期需求答复不批准用户尚未看到的审查；已经有效批准的事项不重问。

## 固化成稿输入

主线程留存完整裁决，在本线程核对原话、范围和版本。给成稿方单独编制已批准的主张、修正、必要事实和说明。授权字段只写版本、授权状态及生效范围或批准项编号。含否决项的原话不能随任一字段传递。按 protocol.md 编制 `WRITER_PACKET`。

不传全部访谈、原生卡片历史、已放弃方向、反问过程、已排除审计或“还有未列出的风险”等暗示。必需原始证据仍完整保留，包括影响结论的反证和事实身份。输入过滤针对无效讨论，不过滤核对主张所需的事实。
