# 完整红蓝与一次成稿协议

仅供完整审查路线使用。流程为独立蓝方论证、独立红方审计、主线程提请裁决、全新成稿方写作、主线程有限核查。已有有效输入和裁决时，从当前阶段接续。

## 准备与隔离

主线程为当前材料标明版本，并准备两个输入包：

- `T` 记录写作问题、受众、体裁、交付语言、目标期刊或体裁语体、拼写体系（US/UK）、篇幅、用户直觉、已选主线、交付阶段和允许改动的范围。
- `E` 记录证据编号、出处、原文或可核对的摘录、日期及必要上下文。分清事实、用户假设和推断。补证用增量编号。主线程在授权范围内查证，或把关键缺口写入材料。

主线程直接创建三个独立的新上下文，只传下文指定的输入和对应角色指令。工具提供 `fork_turns: "none"` 时显式使用，其他工具须核对新建代理的历史继承方式；若宿主无法关闭父会话历史继承，视为不满足隔离条件，按下方降级条款处理。工作代理只处理分配的材料，通过主线程返回缺口和提问建议。主线程负责联系用户及传递材料。角色代理不读取其他会话、记忆或未分配文件，不联系其他角色或再委派。此约束针对历史和输入。宿主可能仍共享文件系统或系统指令。

无法建立独立上下文时，说明当前能完成的阶段与限制，交付可在新会话使用的自包含角色输入包（仅含当前阶段必需的 `T`/`E` 与角色指令，严格剥离父会话标记、历史对话与无关元数据）；不要把同一上下文里的角色扮演称作已实现隔离。若用户明确了解该限制并确认只需当前会话单线推进，可按分阶段方式继续，并在交付中标明未经独立上下文隔离审查。成稿包仍待裁决后生成。

## 蓝方和红方

以下是交给角色的指令。主线程补上对应输入和必要的方法摘录。

**蓝方**接收 `T`、`E` 和 [论证展开](argument.md) 中与任务相关的部分（含跨学科范式校准与豁免）。沿用户直觉提出可检验的解释，接合相互支持的主张、推演连接和验证方法。文献驱动时使用 [文献立论](literature.md)，交代最近前作、推断增量与改判条件。获准补查的新证据先交主线程编入 `E`。

> 输出 `BLUE_PACKET`。给出核心结论和结构提纲。每个 `B` 项写出主张及其事实身份、证据编号、连接理由、关键前提、可检验预测或具体意义，以及需要补证的缺口。保留有依据的大胆假设并标明身份。只提供可核对的论据与推算，交付停在论证阶段。

**红方**接收 `T`、`E`、`BLUE_PACKET` 和下方分级表。核对承重事实、引用、计算、因果和论据是否足够。检查前提、实质反例、可区分的替代解释及其对结论的实际影响。缺少直接验证的明确假设按前提与推演审查。

> 输出 `RED_PACKET`。每个 `R` 项写明对应的 `B`、可核对证据、严重性、实际影响和最小修正。允许零项。以问题证据确定严重性，交付审计结果。

| 级别 | 如何处理 |
| --- | --- |
| P0 阻断 | 关键事实或证据不成立，或核心结论、行动选择会失效。主线程组织修正、补证或撤回，提交用户裁决。 |
| P1 非阻断 | 对理解或使用有具体影响。由用户决定是否保留，按交付体裁安排位置。 |
| P2 可省略 | 旁枝、泛泛可能性、重复限定或风格顾虑。留在审计记录即可。 |

确认的事实、算式或引文错误按最小范围修正。若修正影响核心主张，则进入裁决。

## 人工裁决

主线程向用户呈现推荐主线、承重证据、实际存在的 P0/P1 及建议处理。按 [主线程协调](coordination.md) 安排合并或分阶段裁决，用 [单项决策](decision-interaction.md) 提问和接续。等待时保持 `WAITING_FOR_HUMAN`。

**用户明确裁决了当前材料、阻断项已有有效处置且获得成稿授权后，才启动成稿方。** 用户可以整体采纳已展开的方案。早期选题或同意尝试流程的答复只在其原范围内有效。若争议涉及已证伪事实，修正、撤回，或将仍可成立的部分写成明确假设。未解决的阻断项所影响的主张继续待判。

## 成稿交接

主线程据实际裁决生成 `WRITER_PACKET`。原始裁决和审计记录留在主线程。

| 字段 | 传给成稿方的内容 |
| --- | --- |
| `T` | 生效的任务、受众、体裁、交付语言、目标期刊或语体、拼写体系（US/UK）、篇幅、写作范围和主线 |
| `E*` | 成稿核对所需的原始证据、出处和上下文，包含影响结论的反证及负面结果 |
| `B*` | 裁决后主张、证据身份、关键前提、论证连接和段落方向 |
| `EDITS_APPROVED` | 已接受的具体修正和目标表述（英文交付时，目标表述直接用英文给出，或以“主张 + 强度 + 条件”的语义约束传递；不传中文表层措辞供成稿方直译） |
| `NOTES_APPROVED` | 获准保留的非阻断事项及其证据编号 |
| `DECISION` | 材料版本、实际成稿授权状态和生效范围或批准项编号 |

原始反证进 `E*`，关于它的审计讨论留在主线程。把混合「采用甲、删去乙」的答复拆为生效结果。各字段仅传获准内容及核实它所需的材料，排除原聊天、完整审计、角色争论、已否决意见和暗示另有未列风险的元提示。修正若需重建论证，先由主线程或原蓝方只处理相关修正，再核对结果与裁决相符。

**成稿方**在裁决后新建，只接收 `WRITER_PACKET`、下列角色指令、[表达与保真](expression.md) 的相关规则，以及 [发现与论证展开](argument.md) 中的“跨学科范式校准与豁免”、“展开方法：让证据完成推理工作”与“意义、必要性与充分性”三节（不传候选探索规则、审稿争论或任何审计过程）。`T` 要求英文交付时同时传入 [英文学术表达](english-prose.md)，成稿方直接按英文段落组织成稿，不先写中文再逐句翻译。

> 根据 `B*` 与 `E*` 完整展开一次正文，落实 `EDITS_APPROVED` 中的具体修正与目标表述，将判断、推理连接、依据及意义充分展开并连成论证，确保落入 `T` 规定的篇幅区间。遵守 `T` 的体裁、学科语体与范围。保留对象、条件、比较口径、事实身份和证据强度；无排除依据时不将局部机制拔高为唯一途径。通过自然学术句法标明实测、仿真、推导或史料来源，不在正式正文中另起一句写入“该结果属……而非……”式审稿核查腔或内部标签。按交付体裁安置 `NOTES_APPROVED`。不主动扩写未授权的反方观点、人工已省略的细节或泛化免责声明。当新发现的承重冲突会改变已裁决主张时，返回 `NEEDS_HUMAN_DECISION` 并指出具体主张与证据，暂停该部分。

## 成稿后的有限核查

主线程对照裁决、`B*` 和 `E*` 核查一次最终正文。优先排查三类高风险偏差：（1）表述强度越界或推理缩水，例如把相关写成因果、把条件结果泛化、把“无法单独解释某现象”拔高为“证实单一机制”、把假设或模拟写成实测，或漏掉 `B*` 中已批准的关键推理连接；（2）跨范式惯性与语体泄漏，例如给纯数学或质性研究强加实验要求、泄漏“该结果属……而非……”审稿核查腔或内部标签；英文稿另按 `english-prose.md` §8 排查证据强度动词漂移、英文元标签与译文腔；（3）数值、方向、出处、目标篇幅区间、错字与版式偏差，按 [表达与保真](expression.md) 一并核对。

对有明确依据的越界句做最小局部修正，恢复已批准的主张与证据强度。核查范围限于裁决后的稿件与依据，不重新展开红蓝审查。若成稿方触发 `NEEDS_HUMAN_DECISION` 或核查发现会改变裁决的新 P0，主线程剥离内部协议标记，暂停受影响主张的交付，按 [单项决策](decision-interaction.md) 将冲突转化为单个问题交由用户裁决，并保留其他有效决定。交付按 `T` 的体裁完成，不再附带主线程自己的防御性尾注或内部状态令牌。
