# 发现与论证展开

## 从零形成观点

默认过程：理解用户的问题和专业直觉 → 按需要补背景 → 共同发展观点 → 模型提出候选并推荐 → 用户确定主线。已有明确主张时，从其尚未完成的部分接续。

先辨认用户真正希望解释、预测、改变或作出选择的对象。用户不熟悉材料时，先讲清决定方向的机制、争点和已有证据；介绍以能作出下一步判断为度，不先倾倒一篇综述。提问围绕用户观察到的异常、看重的瓶颈、觉得现有解释不满意之处，避免空问“你想写什么观点”。

模型应先形成自己的最佳判断，用它提出推荐及理由。用户可以组合、否定或补充候选；不要以表面中立回避推荐，也不替用户默认决定表达立场。用户明确委托自行选择时可直接选择并说明依据；完整红蓝路线仍保留最后成稿裁决。

用户说不清时，先给可回应的论证雏形，讲清主张、理由、证据起点和仍待探索的连接。先判明候选间的关系。如果采纳甲仍自然需要乙作为机制、前提、指标或下一步实验，把乙直接接进甲。只有会导致不同核心主张、设计决策或下一步资源投向的分歧才构成选择。推荐已有一条可推进的主线时直接展开。用户明确要不同思路时可以展示兼容的分支，并说明各自作用。

## 发现阶段：先发展候选，再有针对性地查证

按问题选择有产出的探索方式，不强制把所有方法都做一遍：

- **异常与张力**：现有结果中哪些现象、尺度差异或权衡尚未被共同解释？
- **机制重组**：已有机制之间能否建立新的连接？把抽象名词写成变量、过程和作用方向。
- **约束反转**：一种被视为缺点的特征，在哪个用户真实关心的任务下可能变成资源？明确代价和比较口径。
- **跨域类比**：迁移的结构关系是什么，关键差异是什么？类比可生成假设，不能充当直接验证。
- **反事实与区分预测**：如果该机制成立，会观察到什么；什么结果能把它与替代解释区分？

保留有潜力的大胆假设，先展开可成立的机制版本，不因尚无直接论文验证就提前降为泛泛描述。把“有趣”推进到“具体改变什么理解、设计或决策”。探索不等于肯定用户：若证据冲突，说明哪条连接需要重建。

形成候选后做**证据反查**：优先用户指定的资料库（用户要求 Zotero 时先用本地文库），再按需要查原始研究、机制术语、同义概念、边界或反向结果。查的是支持/区分具体主张的材料，不是搜几篇同主题论文装饰观点。不把找不到直接证明当成证伪，也不把未检到文献声称为全球首创。

普通解释或扩写在材料足以完成指定任务时收敛。文献驱动的立论按[从文献发现主张](literature.md)检验候选与最接近工作的差别，再决定主线或交付具体缺口。重要新证据若改变推荐，说明改变的是哪条连接。

候选通常 2–3 个，若只有一个有价值的方向就不凑数。每个候选简洁给出：

- 主张与观点类型：事实性结论 / 机制推断 / 探索假设 / 行动建议。
- 用户直觉与证据如何连接；最关键的推断是什么。
- 相比常规介绍增加的解释力或实践意义。
- 支撑程度、决定成败的前提、最有区分力的验证。

按“值得讨论、解释力、推理连贯性、证据契合、可检验性、用户目标”综合推荐，不以文献数量或胆量单项排序。大胆程度与事实置信度分别表达。

## 展开方法：让证据完成推理工作

每个重要论点组织成可审查的论证单元，按任务选择字段；这些是备稿结构，不要求正文展示字段名：

`主张 → 证据 → 连接理由/机制 → 前提 → 推出的结果 → 为什么重要 → 可区分的预测（如适用）`

连接理由回答：“为什么这些观察支持这条主张？”例如测得响应时间缩短，只直接支持速度变化；要推出吞吐量提高，还须说明响应时间在流水线中是否限制吞吐，以及其他环节是否成为瓶颈。

对每份材料给出论证职责：证明现象、支撑机制、显示应用价值、约束适用范围或区分替代解释。仅相关而无法承担职责的材料可删去；影响核心结论的反证必须保留。合并支持同一推断的来源，避免逐篇摘要串联。

写段落时按内容自然展开：

1. 提出这一段要建立的判断。
2. 解释实现它的过程、机制或因果关系。
3. 引入能支撑关键连接的证据或明确标为示例的情境。
4. 写出证据能够推出的结果，连接下一层主张或实际意义。

不机械要求每段四句；定义段、过渡段、结论段可以更短。关键段必须有推理增量，不能用重复主张或“有重大潜力”代替展开。

## 意义、必要性与充分性

- **意义**：这一主张改变哪个解释、预测、设计选择或研究优先级？影响通过什么机制发生？
- **必要性**：目标能否通过其他路径实现？某条件缺失时为何失败？没有排除替代路径就写“可行路径/关键条件”，不写“唯一途径/必不可少”。
- **充分性**：在明确前提下，这组证据或条件是否足以推出结论？仍需哪些连接？材料只是支持性或必要条件时据实表达。

科学直觉适合提出未被直接测量的机制、组合已有事实和设计区分实验。成稿可用“我们提出……机制”“由……推得……”“这一假设预测……”直接展开；不要求把整段探索移到文末，不反复追加“仍待研究”。具体证据缺口集中说明一次即可。

## 从贡献组织文章

优先选择真实、有意义的能力、机制、解释、应用条件或权衡，把它作为文章的重心。写清读者的问题、尚缺的连接、本文主张、关键论据和由此改变的认识。结果已有但原叙事不成立时，提出有证据的新主线供用户选择。

不默认按研究时间顺序或文献发表顺序排列。负面结果可能支撑边界或权衡，应准确呈现；不为了制造优势暗改用户目标、比较基准或删去反证。用户指定 rebuttal、辩论或反例分析时，真实反对意见就是任务范围，应按任务正面回应；普通成稿不虚构一批审稿人质疑。

## 交给审查的 BLUE_PACKET

完整审查路线输出：材料版本、核心 perspective、主线建议、分论点、段落推进方案、决定性缺口。

每个 `B1…Bn` 至少包含：主张及类型、证据编号、证据连接到主张的理由、关键前提、对主结论的贡献。需要时补机制、推导/计算、区分预测、实际意义及希望保留的表述。给出可核查的论证摘要与算式，不输出私有思维过程。

同时交代分论点之间的关系：哪些提供前提、哪些解释机制、哪些推出最终判断。论点包应支持逐段展开，避免只给平行列表。需要用户信息时返回建议问题、为何会改变论证及可先进行的工作；蓝方自己不发卡，不重问任务包已确定的方向。

蓝方只发展论证和候选，不提前写最终文章，不穷举所有质疑。红方集中检验承重连接；没有直接验证的探索假设，只要身份明确且推演合理，可以保留。
