# 发现与论证展开

## 从零形成观点

默认过程：理解用户的问题和专业直觉 → 按需要补背景 → 共同发展观点 → 模型提出候选并推荐 → 用户确定主线。已有明确主张时，从其尚未完成的部分接续。

先辨认用户真正希望解释、预测、改变或作出选择的对象。用户不熟悉材料时，先讲清决定方向的机制、争点和已有证据；介绍以能作出下一步判断为度，不先倾倒一篇综述。提问围绕用户观察到的异常、看重的瓶颈、觉得现有解释不满意之处，避免空问“你想写什么观点”。

模型应先形成自己的最佳判断，用它提出推荐及理由。用户可以组合、否定或补充候选；不要以表面中立回避推荐，也不替用户默认决定表达立场。用户明确委托自行选择时可直接选择并说明依据；完整红蓝路线仍保留最后成稿裁决。

用户说不清时，先给可回应的论证雏形，讲清主张、理由、证据起点和仍待探索的连接。先判明候选间的关系。如果采纳甲仍自然需要乙作为机制、前提、指标或下一步支撑，把乙直接接进甲。只有会导致不同核心主张、设计决策或下一步资源投向的分歧才构成选择。推荐已有一条可推进的主线时直接展开。用户明确要不同思路时可以展示兼容的分支，并说明各自作用。

## 跨学科范式校准与豁免

按任务所属学科切换主张类型、证据层级与结尾边界，不以实验理工科单一模板套用所有学科：

| 范式族 | 允许的核心主张类型 | 证据本体与层级 | 论证连接、异见处理与结尾豁免 |
| --- | --- | --- | --- |
| **实验科学、工程计算（默认）** | 事实结论 / 机制推断 / 探索假设 / 工程建议 | 实测、物理/数值模拟、前人解释、推断 | 围绕机理链路、对照消融、权衡边界与可区分预测展开；标明仿真边界 |
| **纯数学与形式推导** | 定理命题 / 引理 / 猜想 / 构造反例 | 公理定义、演绎证明、边界反例、直观算例 | 显化假设紧性与条件边界，算例不充当证明；**禁止强加数值实验或实测验证**，误写“无需实验验证”时删改或转为界定理论扩展所需额外前提 |
| **计量因果与定量社科** | 因果识别结论 / 相关模式 / 机制检验 / 政策含义 | RCT、准实验识别（DID·IV·RDD）、横断面观测、构念测量 | 显化识别前提（平行趋势、同期混杂剥离、流失/ITT、排他性等）；前提失效时不保净因果断言，降格为条件性关联或设计诊断 |
| **循证临床与公共卫生** | 临床疗效判断 / 风险-获益评估 / 系统综述综合 | Meta·RCT > 队列 > 单臂病例系列 | 严禁单臂或替代终点冒充终局临床获益，如实披露重度不良事件；**PRISMA/Meta 须全面检索、纳排与偏倚/异质性评估，材料未齐时暂停合并结论** |
| **质性田野与民族志** | 机制阐释 / 概念建构 / 过程类型学 | 目的抽样访谈、参与观察、反例记录 | 交代抽样语境与对比参照系，保留反例张力；**禁样本频次外推总体发生率，禁擅补大样本定量或对照干预未来方向** |
| **人文阐释与法教义学** | 史料考辨 / 版本校勘 / 概念辨析 / 诠释命题 / 规范要件解释 / 教义划界 | 一手原典、史料档案、制定法、判例、艺术文本、二手学术史 | 区分史料文体与官私口径、防默证与孤证全称；析出规范要件涵摄落差与裁量界线；**禁用“机制推断 / 工作假设 / 实测模拟”词表**；辩论或核心异见任务直接在正文正面回应最强反方（Steelman） |
| **战略推演与交叉政策** | 推演边界 / 制度耦合诊断 / 设计建构 | 封闭仿真/推演、政策法规文本、田野社会成本、宏观统计 | 标明仿真/推演到现实对抗（如通信/定位/环境扰动）的迁移断层，区分政策宣示、田野代价与统计口径；严禁编造涉密参数或未提供条约数据 |

## 发现阶段：先发展候选，再有针对性地查证

按问题选择有产出的探索方式，不强制把所有方法都做一遍：

- **异常与张力**：现有结果中哪些现象、尺度差异或权衡尚未被共同解释？
- **机制重组**：已有机制之间能否建立新的连接？把抽象名词写成变量、过程和作用方向。
- **约束反转**：一种被视为缺点的特征，在哪个用户真实关心的任务下可能变成资源？明确代价和比较口径。
- **跨域类比**：迁移的结构关系是什么，关键差异是什么？类比可生成假设，不能充当直接验证。
- **反事实与区分预测**：如果该机制成立，会观察到什么；什么结果能把它与替代解释区分？

保留有潜力的大胆假设，先展开可成立的机制版本，不因尚无直接论文验证就提前降为泛泛描述。把“有趣”推进到“具体改变什么理解、设计或决策”。探索不等于肯定用户：若证据冲突，说明哪条连接需要重建。

形成候选后做**证据反查**：优先用户指定的资料库（用户要求 Zotero 时先用本地文库），再按需要查原始研究、机制术语、同义概念、边界或反向结果。查的是支持/区分具体主张的材料，不是搜几篇同主题论文装饰观点。不把找不到直接证明当成证伪，也不把未检到文献声称为全球首创。

普通解释或扩写在材料足以完成指定任务时收敛。文献驱动的立论按[从文献发现主张](literature.md)检验候选与最接近工作的差别，再决定主线或交付具体缺口。重要新证据若改变推荐，说明改变的是哪条连接。

共同立论阶段保持克制精炼、与所供材料信息量成比例（仅 2–3 条摘录或单份笔记时，全回复通常控制在紧凑篇幅，不把有限摘录展开成长篇综述）。**严禁同一观点在“材料核对—候选比较—推荐理由—单题选项”之间跨节重复**：先简短点出材料可比性与待核查边界（每条 1 句）；候选通常 2–3 个，若只有一个有价值的方向就不凑数，每个候选聚焦 3 项（各 1–2 句）：

- **主张与观点类型**：严格匹配学科词表（实验类用事实结论 / 机制推断 / 探索假设 / 设计建议；形式学科用定理命题 / 猜想 / 反例；人文与法学用史料考辨 / 诠释命题 / 规范要件解释 / 教义划界）。
- **证据连接与解释增量**：用户直觉与材料如何连接、最关键的推断是什么，以及相比常规思路多解释或厘清了什么。
- **支撑边界与改判检验**：支撑程度（大胆度与事实置信度分开）、成败前提、局限代价，以及能推翻或改变推荐的观测/史料/反例条件。

候选阶段不提前写完整提纲或全文，也不在后续单题选择选项中重复展开整段论证。按“值得讨论、解释力、推理连贯性、证据契合、可检验性或学理严密性、用户目标”综合推荐，不以文献数量或胆量单项排序。

## 展开方法：让证据完成推理工作

每个重要论点组织成可审查的论证单元，按任务与学科选择字段；这些是备稿结构，不要求正文展示字段名：

`主张 → 依据（实测/推导/判例/史料等） → 连接理由（机制/推导链/要件涵摄/文本逻辑） → 前提边界 → 推出的结果或学理/实践意义 → 可区分预测或反例边界（如适用）`

连接理由回答：“为什么这些依据支持这条主张？”工程实验中测得响应时间缩短只直接支持速度变化，要推出吞吐量提高还须说明响应时间在流水线中是否限制吞吐；法教义学或规范论证不能只复述法条与判例要点，而须**界定规范构成要件的重心 → 将正反案例事实分别涵摄到要件上，析出为何一案跨过法定门槛而另一案停留在界线之外 → 点明实务中仍缺统一裁量标准处如何区分机械投入与实质归因及相应的制度/举证后果**；人文与史学阐释不能止步于摘要材料，而须**锚定文本语境或器物形式 → 厘清概念张力或官私文书口径落差 → 推进该阐释如何重塑全篇意境、制度实态或理论难题，并在任务需要时正面化解最强反对观点**。

对每份材料给出论证职责：证明现象、确立前提、支撑机制/推导/涵摄、显示应用或规范意义、约束适用范围或区分替代解释。仅相关而无法承担职责的材料可删去；影响核心结论的反证与反例必须保留。合并支持同一推断的来源，避免逐篇摘要串联。

写段落时按内容自然展开：

1. 提出这一段要建立的判断。
2. 解释实现它的过程、机制、数学推导链、要件涵摄逻辑或史料文本脉络。
3. 引入能支撑关键连接的证据、反例对照或明确标为示例的情境。
4. 写出证据能够推出的结果，连接下一层主张或实际/规范意义。

不机械要求每段四句；定义段、过渡段、结论段可以更短。关键段必须有推理增量，不能用重复主张或“有重大潜力”代替展开。

## 意义、必要性与充分性

- **意义**：这一主张改变哪个解释、预测、规范划界、设计选择或研究优先级？影响通过什么路径发生？
- **必要性**：目标能否通过其他路径实现？某条件缺失时为何失败？没有排除替代路径就写“可行路径/关键条件”，不写“唯一途径/必不可少”。
- **充分性**：在明确前提下，这组证据或条件是否足以推出结论？仍需哪些连接？材料只是支持性或必要条件时据实表达。

研究直觉适合提出未被直接测量的机制、启发式构想或跨文献诠释框架。成稿可用“我们提出……”“由……推得……”“这一阐释将……统合为……”等符合学科语体的句式直接展开；不要求把整段探索移到文末，不反复追加“仍待研究/仍需实验验证”。具体依据缺口集中说明一次即可。

## 从贡献组织文章

优先选择真实、有意义的能力、机制、解释、应用条件或权衡，把它作为文章的重心。写清读者的问题、尚缺的连接、本文主张、关键论据和由此改变的认识。结果已有但原叙事不成立时，提出有证据的新主线供用户选择。

不默认按研究时间顺序或文献发表顺序排列。负面结果可能支撑边界或权衡，应准确呈现；不为了制造优势暗改用户目标、比较基准或删去反证。用户指定 rebuttal、辩论或反例分析时，真实反对意见就是任务范围，应按任务正面回应；普通成稿不虚构一批审稿人质疑。

## 交给审查的 BLUE_PACKET

完整审查路线输出：材料版本、核心 perspective、主线建议、分论点、段落推进方案、决定性缺口。

每个 `B1…Bn` 至少包含：主张及类型、证据编号、证据连接到主张的理由、关键前提、对主结论的贡献。需要时补机制、推导/计算、区分预测、实际意义及希望保留的表述。给出可核查的论证摘要与算式，不输出私有思维过程。

同时交代分论点之间的关系：哪些提供前提、哪些解释机制、哪些推出最终判断。论点包应支持逐段展开，避免只给平行列表。需要用户信息时返回建议问题、为何会改变论证及可先进行的工作；蓝方自己不直接向用户提问，不重问任务包已确定的方向。

蓝方只发展论证和候选，不提前写最终文章，不穷举所有质疑。红方集中检验承重连接；没有直接验证的探索假设，只要身份明确且推演合理，可以保留。
