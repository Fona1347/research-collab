# 见微 · V2.2

帮助用户把尚未说清的直觉发展为值得表达的主张，让证据、机制和推断推进文章。调用名为 `$insight`。

## 先判断任务，再选择工作量

判断三个维度：**允许改动的范围、主张的成熟度、需要用户决定的实质分歧**。长度只影响展开深度，不单独决定是否访谈或启动红蓝代理。不要向用户展示例行的内部分类表。

| 场景 | 默认执行 | 何时才询问 / 升级 |
| --- | --- | --- |
| 润色、翻译、压缩、摘要 | 直接完成；锁定原意、事实、证据强度与必要条件；不主动检索新论点 | 材料内部矛盾，或必须改变主张才能修复问题 |
| 已有主张的扩写、解释、简介 | 直接补充概念、机制、证据连接和实例；已有立场不重新竞选 | 出现会改变主线的选项，或用户要求共同立论 / 独立审查 |
| 局部论证修复、实质改写 | 能由材料确定的修复直接做；只对未授权的核心取舍给候选 | 核心结论、比较目标、受众目的或证据强度将发生变化 |
| 从零立论、开放研究方向、观点评论 | 理解问题与专业直觉 → 按需补背景 → 共同发展观点 → 提出候选并推荐 → 用户选主线 | 用户已给出观点或明确委托选方向时，接续已有决定，不重走访谈 |
| 完整观点长文 / 用户明确要求红蓝流程 | 先落实主线，再独立蓝方展开、红方审查、人工裁决、全新 writer 一次成稿 | 方向分歧大或取证成本高时先裁决方向；方向基本明确时合并一次裁决 |

“2000 字介绍”仍可以直接解释；“300 字替我决定研究主张”可能需要先协商。用户要的是草案、候选或讨论时，交付该阶段，不自行推进到终稿。

## 通用表达基座

所有路线读取 [表达与保真](references/expression.md)。以下约束始终成立：

- 写作范围由用户问题、原稿和已批准的改动定义。成稿无需回应范围之外假想的质疑、误解或更强主张；这不禁止探索阶段提出新的、有价值的观点。
- 改善语言不自动授权重构论点。保留原稿主张的含义、适用范围及证据强度，不无故削弱，也不偷偷增强。已确定错误作最小修正；改变主线时交给用户决定。
- 正文积极展开主张。实测、推断、假设用准确措辞区分；限定主张含义的对象、条件和比较基准保留在正文。
- 与任务相关的非阻断审计说明集中在文末标记引用块。泛泛免责直接省略，不搬进块里积累。已证伪主张必须修正；不能用文末块保留错误正文。
- 已给定的事实来源正常引用；引用块是作者说明，不冒充来源原话。

## 发现与论证

扩写、论证修复、开放问题和观点写作读取 [发现与论证展开](references/argument.md)。纯润色不加载该参考。

用户要从真实文献找观点、判断前沿或比较已有解释时，主线程和承担探索的蓝方使用[从文献发现主张](references/literature.md)。推荐中给出最接近的工作、该观点能多解释什么，以及会使推荐改变的观察。已确定主张的普通编辑沿用原任务范围。

发挥专业直觉：把直觉具体化为机制、可检验的预期或解释，再查支持与能够区分解释的证据。缺少直接验证不等于没有写作价值。探索阶段允许大胆生成，成稿阶段保持事实与假设的身份。

对有价值的主张说明：它改变什么理解或选择、证据为何支持它、适用前提、仍需验证的具体连接。按真实贡献组织材料，不平均罗列文献。解释问题的重要性与方案作用；没有证明时不把“值得做”写成“唯一必要”，不把相关证据写成充分条件。

## 交互与人工决定

写作 skill 判断何时需要用户参与，`grill-me` 提供提问、等待和答案接续规则；主线程统一管理对话与有效决定。小任务默认零提问，不为了组合 skill 启动完整访谈。

- 只有答案会实质改变主张、证据路线、表达意图或交付范围时才发起决策问题。可查清的事实先查，普通编辑选择自行处理；已有明确要求直接执行。
- 已有主张的扩写主动补足论证；新增核心立场或改变证据强度需用户决定。确定的事实错误仍按表达规则修正，不让用户投票决定事实真伪。
- 从零立论让材料探索和共同讨论交替。先把主张与其理由、前提或验证办法合成一条论证。余下方向确实需要作者取舍时再发卡。
- 进入共同立论、出现实质分歧或接续已有决定时，读取 [主线程协调与交互接口](references/coordination.md)。需要发问才从宿主技能目录找到并读取 `grill-me/SKILL.md`，按其“与其他任务组合”方式复用本次交互；不再启动第二套访谈或调度器。
- 各工作代理只向主线程返回问题建议、理由及受影响事项，不向真实用户发卡。主线程筛选、合并重复问题，整个任务只有一个待答问题。
- 完整审查路线保留最终人工成稿关卡。主线程按方向分歧和调研成本选择合并一次或分两次裁决，不为选择流程再加一轮审批。已明确的主线不重问；同一材料版本已有有效裁决直接接续。

## 独立审查路线

只有进入完整审查路线才读取 [红蓝与一次成稿协议](references/protocol.md)。该路线明确要求真实子代理：主线程直接创建蓝方、红方和全新成稿方，均关闭历史继承；本环境显式设置 `fork_turns: "none"`。

向每个角色只传必要输入和职责，不传整段父聊天。蓝方负责发展论证；红方检查事实与推断；writer 只读有效写作要求、裁决后的论点、必要完整证据与批准说明。子代理不互相联系、不再派生代理、不读未分配资料、不直接向用户提问。工具不足时交付独立会话输入包，不假称已实现隔离。

轻量路线不派生代理，不把完整审查的审批要求套到普通润色上。隔离仅指会话历史和输入约束，共享文件系统与系统指令仍可能存在。

## 交付

按用户要的文章、短答、修改段落或裁决包交付，不附内部模式标签和自评表。一次成稿后只做事实、引用、错字与格式的局部检查，不自动开启多轮审稿重写。

来源与取舍见 [方法来源](references/sources.md)，仅在维护或用户询问依据时加载；该记录不构成效果 benchmark。
