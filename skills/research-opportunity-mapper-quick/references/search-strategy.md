# Search and Evidence Strategy

## Search Objective

Search has three distinct purposes:

1. Understand the persistent problem and strongest existing baseline.
2. Identify mechanism families and direct neighbors.
3. Try to disprove the opportunity claim.

Do not combine these purposes into one oversized query.

## Query Lattice

Build queries by combining one term from each relevant column:

| Layer | Query dimensions |
|---|---|
| Workload | application, model family, data type, operating environment |
| Bottleneck | bandwidth, movement, latency, energy, memory capacity, adaptation, calibration, conversion, communication |
| State operation | store, update, forget, select, compress, integrate, differentiate, sample, gate, couple |
| Mechanism | polarization, ion motion, charge trapping, phase transition, magnetization, photocarrier, thermal state, mechanical state |
| Device | transistor, junction, memory, sensor, oscillator, resonator, array, heterogeneous stack |
| Failure | variability, drift, retention, endurance, nonlinearity, sneak path, parasitic, peripheral overhead, scaling |
| Evidence type | benchmark, review, prototype, array, circuit, system, negative result, patent |

Use synonyms and neighboring terminology. A sparse exact-phrase result may mean the community uses different words.

## Search Waves

### Wave 1: Vocabulary and topology

Search broad concepts and recent reviews. Extract terminology, architecture families, metrics, and canonical references. Reviews orient the map but do not replace primary evidence.

### Wave 2: Representative primary evidence

Retrieve primary papers for each branch, including recent demonstrations and strong baselines. Verify title, authors, year, venue, DOI, and whether the paper actually contains the claimed result.

### Wave 3: Direct-neighbor search

For each candidate, search the complete combination and its decomposed parts. A candidate may look novel only because two mature literatures use different vocabularies.

### Wave 4: Disconfirmation

Search failure terms, contradictory results, skeptical reviews, scaling limitations, peripheral overhead, and digital alternatives. Search the strongest competitor by name.

### Wave 5: Translation and priority

When commercialization, priority, or ownership matters, search recent major conferences, preprints, patents, company disclosures, and grants. This is still not a legal freedom-to-operate analysis.

## Sciverse Retrieval Pattern

When Sciverse tools are available:

1. Call catalog/schema discovery when searchable fields are unknown.
2. Use semantic search for broad concept discovery and relevant passages.
3. Use structured paper search for year filters, DOI resolution, exact titles, venues, and reproducible lists.
4. Use content reading for context around decisive claims.
5. Use relationship or seed expansion for citation neighborhoods when available.

The evidence record should retain `doc_id`, `chunk_id`, `offset`, `page_no`, or the closest available locator. Record when a result was found only at abstract level.

## Inclusion Logic

Default inclusion:

- Primary research that directly measures the claimed mechanism or system bottleneck.
- Recent reviews that define terminology or synthesize a branch.
- System or circuit papers that quantify end-to-end overhead.
- Negative or mixed evidence.
- Older canonical sources only when necessary to define a mechanism or baseline.

Default exclusion:

- Papers selected only because the title contains fashionable keywords.
- Device demonstrations with no relevant mechanism or system metric.
- Unverified citations generated by a model.
- Duplicate preprint and published versions unless version differences matter.
- Claims available only through secondary summaries when the primary source is accessible.

Adapt the date window to the task. If the user asks for 2023-present, keep older sources only as clearly marked canonical background.

## Evidence Depth

Use three levels:

- `Metadata`: enough to establish existence and bibliographic facts.
- `Passage`: enough to support a bounded textual claim.
- `Full context`: methods, figures, supplementary information, or surrounding discussion inspected for a consequential claim.

Final recommendations should not rest only on metadata or snippets.

## Search Misses

Record misses because they guide subsequent queries, but phrase conclusions carefully:

- Acceptable: "No direct match was retrieved from databases X and Y using queries Q1-Q6 on DATE."
- Not acceptable: "Nobody has studied this."

A miss can indicate terminology mismatch, indexing delay, inaccessible proceedings, patents, non-English literature, unpublished work, or a genuinely sparse area. Classify it as `bounded negative evidence` and schedule a close-match search.

## Coverage Stop Rule

Stop expanding a branch when all are true:

- New queries mostly return already-seen direct neighbors.
- The bottleneck and strongest baseline are supported by direct evidence.
- The mechanism claim has primary evidence and at least one limitation source.
- The candidate has a bounded crowding classification.
- Remaining uncertainty is better resolved experimentally or through a named specialized database.

Do not stop merely because a favored candidate already looks attractive.
