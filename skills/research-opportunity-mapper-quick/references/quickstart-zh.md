# 中文快速使用指南

## 这个 Skill 解决什么问题

它不是用来直接生成“十大热门方向”，而是把一个宽泛领域逐层收敛为：

`未来仍会存在的瓶颈 × 可证伪的物理/器件机制 × 课题组可迁移能力 × 有边界证据支持的开放位置`

适合以下任务：博士选题、实验室长期平台规划、基金方向预研、已有想法的去锚定、研究方向的证据化比较。

## 最小调用提示词

```text
使用 $research-opportunity-mapper-quick 调研【领域】。

我要做的决策：【博士课题 / 实验室平台 / 基金方向】。
课题组已确认能力：【工艺、材料、测量、建模、集成】。
硬约束：【三个月首批数据、一年平台、线宽、经费、合作条件】。
文献窗口：【例如 2023 至今】。

先发散并通过 breadth gate，再排序；不要从偏好的材料开始。
请明确区分 Evidence、Inference、Recommendation、Speculation。
每条关键证据保留 DOI/稳定链接、Sciverse doc/chunk/page/offset、
核心贡献、印证观点和局限。检索未命中只能作为有边界的负证据。

最终输出 research map、证据矩阵、低/中/高风险组合、三个月
决定性实验、一年平台路线、最强基线、替代解释、kill criteria、
反转条件和下一轮检索计划。
```

更完整的分阶段提示词见 `prompt-library.md`。

## 新建一次调研

在 Skill 目录中运行：

```powershell
python scripts/init_run.py `
  --domain "你的研究领域" `
  --short-task-name "短任务名" `
  --output "<research-workspace>\runs"
```

脚本会创建“双层交付”：八个互相衔接的内部工作文件，以及一份面向读者的一级主报告。一次运行只有在主报告完成并通过质量门后才算结束。

1. `00_intake.md`：决策、约束、能力护照和未知项。
2. `01_breadth-ledger.md`：防止过早收敛的覆盖账本。
3. `02_search-log.md`：可复现检索式、命中、漏检和下一查询。
4. `03_evidence-matrix.md`：主张级证据与 provenance。
5. `04_research-map.md`：从需求到机制和材料的递进地图。
6. `05_candidate-portfolio.md`：低、中、高风险候选卡。
7. `06_red-team.md`：基线、替代解释、系统代价和终止条件。
8. `07_decision-log.md`：保留方向变化、淘汰原因和反转条件。
9. `map_report_<短任务名>_<YYYY-MM-DD>.md`：中文主导的决策报告，使用正文编号引用和 DOI/稳定链接，不堆叠内部检索定位符。

已有同名目录时，初始化脚本会拒绝覆盖。

默认向用户交付第 9 项；前八项作为检索、证据、推理和红队过程的审计底稿。主报告不能只是八份文件的拼接，也不能要求读者打开证据矩阵后才能理解结论。

## 关键执行顺序

1. 先填能力和时间约束，不提出方向。
2. 用 brainstorming 形成不少于四类瓶颈、四类机制和两个应用场景。
3. 用 literature-review 建立检索矩阵，而不是只搜当前偏好关键词。
4. 用 Sciverse 先语义发现，再结构化核验 DOI/年份，最后展开关键原文。
5. 把论文拆成“原子主张—证据—局限”，不要只做论文列表。
6. 从未解决的因果接口生成候选问题。
7. 用 critical-thinking 搜最强反例、数字基线、外围代价和替代机制。
8. 最后才做低、中、高风险排序，并要求三条路线共享平台。
9. 读取 `reader-report.md`，把已经稳定的证据、地图、组合与红队结论重写为面向读者的主报告。

## 引文块格式

GitHub blockquote 用于证据注释，不等于逐字引用：

> **E-001｜题目（年份），DOI 或稳定链接**
> - 核心贡献：论文实际做成了什么。
> - 印证观点：它直接支持哪一个有边界的主张。
> - 局限：它没有证明什么，或在哪个条件下才成立。
> - Provenance：数据库、doc_id、chunk_id、页码/offset、核验状态。

只有与原文逐字核对过的短句才能加引号。不要把摘要改写伪装成原文引用。

内部工作文件保留 `E-###` 和详细 provenance。面向读者的 `map_report` 改用 `[1]`、`[2]` 等编号，并以 `[!NOTE]`、`[!CAUTION]`、`[!IMPORTANT]`、`[!TIP]`、`[!WARNING]` 标出关键结论、边界、执行提示和风险。每个关键引文块至少说明“核心贡献、印证观点、边界”。

## 完成检查

```powershell
python scripts/validate_run.py "调研目录" --strict
```

`0 error / 0 warning` 只表示结构、覆盖和可追溯性门槛通过，不表示方向已经具备绝对首创性。最终仍需导师判断、专业数据库补检、专利/会议检索和决定性实验。

## 出现过早收敛时

如果某个概念迅速占据整张地图，例如本轮最初的 `device-native selective state-space computing`：

1. 暂停排序，不删除已有证据。
2. 标出哪些术语和假设来自同一篇种子论文。
3. 重新用工作负载、状态类型和系统预算建立根分类。
4. 增加不依赖当前概念的瓶颈与机制分支。
5. 对当前概念执行直接近邻、反例和传统基线检索。
6. 将它降为一个候选分支；只有比较完成后才能重新晋级。

这一过程不是否定好想法，而是防止“第一个合理交集”被误当成“最值得做的交集”。
